# 초기 패치 v1–v15 작업 기록

2026-11-18에 정리한 `ScoreMotion_PATCH_HISTORY_v1-v15.md`를 바탕으로 초기 작업을 되짚었다. 여기서 쓰는 v1–v15는 당시 패치 순서다. 현재 저장소의 Git 태그나 릴리스 번호는 [변경 기록](../CHANGELOG.md)에서 따로 확인할 수 있다.

## 패치 순서

| 단계 | 작업 | 당시 확인된 결과·후속 관계 |
| --- | --- | --- |
| 초기 | Shorts에서 악보 드래그 좌표와 세로 영상 건반 하단 배치 수정 | 미리보기 스케일에 맞춰 좌표를 보정했다. 건반 하단 여백은 v10에서 다시 다뤘다. |
| v2 | 건반 Aurora 발광·악보 팔레트 연동 보정 | 이후 v3에서 벨로시티 반응으로 확장했다. |
| v3 | 벨로시티 기반 건반 색상·반응 프리셋과 설정 저장 | 효과 설정과 WebGL 경로를 연결했다. |
| v4 | Score FX / Keyboard FX 조작 화면 분리 | 기존 설정 ID와 이벤트는 살리고 조작 화면을 나눴다. |
| v5 | 추천 악보 팔레트 연동 | 악보·커서·빛·궤적·오로라에 추천색을 입혔다. |
| v6 | 악보 패널 투명도 추천 | 배경 밝기와 대비에 맞는 반투명도를 제안하고 직접 조절도 남겼다. |
| v7 | Dynamic WebGL2 건반 경계 빛 6종 추가 | 이후 빛의 Y좌표가 뒤집히는 문제를 발견했다. |
| v8 | 경계 빛 위치 보정 및 Ripple Flow·Electric Current 추가 | 카메라 투영 기준으로 좌표를 고쳤다. 당시 WebGL 전 구간 출력은 끝까지 확인하지 못했다. |
| v9 | 긴 SVG를 1,024px 타일로 캐시 | 당시 측정에서 캐시 적중률은 99%를 넘었지만 `drawScore` 병목은 남았다. |
| v10 | 영상 출력 건반 하단 여백·합성 크기 진단 | 건반 누락 원인을 확정하지 못해 v12–v13에서 다시 추적했다. |
| v11 | `drawRevision` 기반 SVG 캐시 갱신 | 모의 시험은 빨랐지만 실제 곡의 병목은 줄지 않았다. |
| v12 | 정적 악보 타일과 GPU reveal 마스크 | 측정 구간에서 `svgDecode=0`을 확인했다. 기호 노출과 다중 SVG 문제는 남았다. |
| v13 | WebGL 건반을 2D 미러를 거쳐 합성 | 원본에는 있으나 720p 최종 출력에서 사라지던 건반을 우회했다. 4K 복사 비용은 더 측정해야 했다. |
| v14 | 오선·기호 분류와 다중 SVG 마스크 수정 | 당시 실제 곡에서 정상 동작을 확인했다. |
| v15 | 짧은 되돌이표 구간의 자동 인식 개선 | 악보를 펼치면 MIDI의 추가 음표를 설명할 수 있는지 비교했다. 복잡한 D.C./D.S./Coda는 당시 다루지 않았다. |

## 당시 측정의 해석

- v9의 `svgCacheHits=8008`, `visibleSvgTiles=8066`은 측정한 출력 구간에서 캐시 적중률이 **약 99.28%**였다는 뜻이다. 전곡 평균은 아니다.
- v11에서는 실제 `drawScore` 구간에서 `drawRevision`이 계속 증가했다. 캐시가 기대만큼 듣지 않아 v12의 GPU 마스크로 방향을 바꿨다.
- v12의 `score` 약 125.96ms → 0.75ms, `compose` 약 138.32ms → 1.21ms는 **특정 단계의 평균**이다. 전곡 출력 속도로 환산할 수는 없다.
- 720p 건반 문제에서는 WebGL 원본과 최종 출력의 픽셀이 달랐다. v13은 그 전달 경로를 우회한 작업이며, 당시 모든 해상도를 확인한 것은 아니다.

## 과거 기록의 제한

초기 메모에는 당시의 `score-motion` 저장소, `studio-v15` 브랜치, ZIP 상태도 나온다. 지금 [ScoreVideo-Studio](https://github.com/fvgozak/ScoreVideo-Studio) `main`의 상태와 섞이지 않도록 이 표에는 넣지 않았다. 현재 코드와 배포 방식은 [README](../README.md)와 [변경 기록](../CHANGELOG.md)에 적었다.
